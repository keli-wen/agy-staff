# agy-staff 0.5.0 — Implementer Delivery

Release date: 2026-08-29. This release implements the workspace and delivery contract from issue #1.

## Highlights

- **Dirty workspaces now produce a decision packet.** `implement` no longer gives a generic clean-tree refusal. It reports the current dirty state and tells the caller when to use `--dirty continue`, an isolated worktree, a separate commit, or an explicit stash.
- **Implement tasks have delivery contracts.** `--delivery diff|commit|pr` selects whether the companion leaves a diff, creates a local commit, or commits, pushes, and creates/updates a draft PR. Obvious task text such as "commit this" or "open a PR" is inferred when the flag is omitted.
- **Continuation is snapshot-based.** A successful implement task records repo/worktree/branch/HEAD/status plus tracked diff and untracked content hashes. A continuation can build on its own dirty result, and refuses with a targeted mismatch when the workspace changed externally.
- **Git delivery is companion-owned.** agy edits and verifies. The companion performs authorized commit/push/PR delivery afterwards, stages exact paths with `git add -- <paths>`, and does not ask for the same delivery approval twice.

## Added

- `--delivery diff|commit|pr`, `--dirty continue`, `--include-baseline`, `--commit-message`, `--pr-title`, `--pr-body`, and `--base` for `implement`.
- Implement task manifests in `.agy-staff/state.json`.
- `skills/implementer/references/workspace-delivery.md` for dirty workspace, continuation, delivery, and side-effect policy details.
- Black-box tests for flag-like inline task text, dirty decisions, dirty continuations, mismatch refusal, local commit delivery, and draft PR delivery with a fake `gh`.

## Changed

- The implementer prompt now tells agy to leave Git delivery to the companion.
- The jobs skill no longer requires a second confirmation after an already-authorized `commit` or `pr` delivery.
- Docs now describe implement delivery contracts instead of a mandatory clean-tree gate.

## Fixed

- Inline task text containing flag-like tokens, such as `git diff --check`, is no longer reinterpreted as companion flags after the first task token.
