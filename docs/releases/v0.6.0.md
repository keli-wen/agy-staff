# agy-staff 0.6.0 — Streaming observation and explicit recovery

## Highlights

Implements [#13](https://github.com/keli-wen/agy-staff/issues/13): background staffer, research, review, implement and their continuations continuously drain AGY streaming JSON and publish bounded per-job observations. Synchronous ask keeps its existing execution path.

- `observe <id>` immediately returns bounded JSON in every state; terminal observations point to the full result without printing it. `wait <id> --timeout 10m` returns the existing final result on completion or an observation on soft expiry; the worker continues. Running snapshots contain five recent tool activities, merged response text, timestamps, explicit truncation and detail pointers within an 8 KiB UTF-8 JSON budget.
- Workers pass the selected timeout to AGY and enforce an independent overall hard limit: default 60m, maximum 120m. Launch `--timeout` configures that limit. Wait/observe never renew it. Hard expiry reports `hard_timeout` with retained logs, last observation, conversation and original configuration when no response is available. A complete response already received is delivered with a warning.
- `continue --job <id> --prompt "..."` and `restart <id>` create linked jobs with fresh budgets, preserving the original terminal record. Continuation inherits the selected job's mode/model/profile instead of an unrelated `state.last` or a later turn's configuration. Recovery can be invoked anywhere within the same worktree and returns to the original cwd. Restart refreshes workspace context. Generic continue rejects unrecorded IDs without searching other worktrees. Recovery remains an explicit orchestrator decision after inspecting partial workspace changes.
- Cancellation stops the job's execution group and identified descendants, escalating after a bounded grace interval. Process birth stamps use a fixed C locale and UTC timezone to protect the worker, execution leader and recorded descendants against PID reuse across caller environments. Cancellation requests stay nonterminal until the report is stored; crashed jobs retain their diagnostics. Transient process-inspection failures preserve the last tracked identities. A restricted host that prevents process inspection gets an explicit diagnostic warning.
- Lifecycle writes use a short lock with unique owner markers so stale-lock reapers cannot delete a successor; snapshot updates stay outside the shared registry. Results and terminal metadata are published before warning-free successful intermediates are removed. Exceptional jobs retain streams/snapshots; existing results, diagnostic logs and AGY conversation storage remain available.
- Crash-without-result reports include dispatch/worker-start evidence, process information, log existence/size and recovery/inspection commands. Canonical skills, generated Pi skills and bilingual references explain attention intervals and host scheduling limits consistently.

The command and storage contract is documented in [REFERENCE.md](../REFERENCE.md#state-and-background-jobs). The agreed design remains in issue #13; this release does not include local blog research material.

## Local trial feedback

Wait now remains silent until a result or soft-expiry snapshot is ready. Removed the unconditional 15-second liveness heartbeat. Skills explicitly call observe before a mid-run progress report and distinguish job observation from host session collection, avoiding repeated short empty polls. A regression test waits beyond the former heartbeat interval and verifies silent waiting plus intact snapshot/result delivery.

The local trial also exposed a terminal race: an observe call budgeted for progress could unexpectedly receive a large final report, then duplicate the pending wait’s delivery. Observe now returns only terminal metadata/result pointers (or bounded failure/recovery metadata); wait/result own full delivery. Exit codes remain status-based, so observe exit 0 does not mean the full report has been delivered.

## Validation

Follow-up validation on 2026-09-08: all 159 offline tests passed, generated Pi skills had no drift, and `git diff --check` passed. The 16 added tests cover crash-preserving cancellation, unrelated/reused PIDs and changed process groups, cancellation across locale/timezone changes, cancellation report publication, complete/empty results at hard expiry, inherited output pipes, transient process-inspection failure, missing-JSON model diagnostics, the 120m timeout ceiling, workspace/configuration recovery, large-record parsing, null detail pointers and competing stale-lock reapers. Existing observation tests now synchronize on published progress and explicitly released results. CI runs `npm test` as well as the generated-skills check, preserving the required job name `Generated skills consistency`. This follow-up used fake AGY and did not rerun the real-AGY smoke tests recorded below.

The offline suite covers parsing, UTF-8 byte budgets, late step updates, soft/hard expiry, wait interruption, observer independence, concurrent lifecycle writes, error/warning compatibility, recovery configuration, result/cleanup races and termination-resistant descendants. Packaging tests check version alignment and the actual npm archive; generated Pi skills are checked separately.

Real AGY 1.1.27 smoke tests on macOS exercise streaming tool output (including a command exiting 7), structured review output, cancellation after a shell tool starts, and a shortened hard deadline after a shell tool starts. Process snapshots check observed CLI/tool descendants and ensure stopped tools do not write completion markers. Reproduce with `AGY_REAL_SMOKE=1 node tests/real-agy.integration.mjs` in an unsandboxed context with an authenticated AGY installation. It makes model calls only in disposable directories and prints the evidence location.

These tests exercise the lifecycle paths requested by [#4](https://github.com/keli-wen/agy-staff/issues/4) and [#8](https://github.com/keli-wen/agy-staff/issues/8). A shortened deadline is not a full-hour endurance test; process observations cover the tested process trees, not every possible daemonization strategy or operating system. Workspace attachment (#9) and permission allowlist granularity (#10) remain separate.
