# agy-staff 0.4.0 — Personas

Release date: _unreleased_. This note is the canonical record for 0.4.0; the GitHub Release mirrors it. One note per release lives in this folder; day-to-day history is `git log` and the tags.

## Highlights

- **Five personas, one invocation surface.** The dual command/skill layers merged into a single skills layer with persona names — `/agy:staffer`, `/agy:researcher`, `/agy:reviewer`, `/agy:implementer`, `/agy:ask` — identical on Claude Code and Codex.
- **`staffer`: general-purpose delegation.** A minimal prompt (task, environment, guardrails — no role, no rules, no output format), so the task text alone shapes the output. Also the route to agy-native tools no specialist covers: image generation via `generate_image` is verified on agy v1.1.15 (a 1024×1024 PNG in ~30s).
- **`reviewer` reviews more than code.** Two flavors, routed by subject: code review (evidence-gathering menu, four review axes, severity-ranked findings) and general review (a multi-angle challenge of a plan, design, or decision). The review template itself is now a neutral skeleton; flavor context travels in the task string, so a non-code review is no longer pulled into a code-review shape.
- **A finished answer is never discarded.** Previously, any non-`SUCCESS` status was fatal even when the complete response had already been produced (for example, one tool call timing out during wrap-up) — the answer was buried inside the error text and failure protocols threw it away. Such runs are now `done_with_warnings`: exit 0, response on stdout, warning on stderr.
- **Self-describing job collection.** The job-start output prints the exact collect command (`wait <id> --timeout <n>m`, sized to outlive the job) and the one-background-wait-per-job rule; `wait` gained liveness heartbeats on stderr.

## Breaking changes

The command layer (`commands/`) is removed; each capability is exactly one skill.

| 0.3 | 0.4 |
|---|---|
| `/agy:research` + `/agy:agy-research` | `/agy:researcher` |
| `/agy:review` + `/agy:agy-review` | `/agy:reviewer` |
| `/agy:implement` + `/agy:agy-implement` | `/agy:implementer` |
| `/agy:ask` + `/agy:agy-ask` | `/agy:ask` |
| *(none)* | `/agy:staffer` (new) |
| `/agy:status` `/agy:wait` `/agy:result` `/agy:cancel` `/agy:continue` `/agy:setup` | the model-facing `jobs` skill — ask in natural language ("is the agy job done?") |

The companion CLI subcommands are unchanged; only the harness-level invocation names moved. Full table with notes: [REFERENCE.md → Migration from 0.3](../REFERENCE.md#migration-from-03).

## Added

- `staffer` mode: unrestricted, background, `gemini-3.7-flash-medium`, 10m default timeout; configurable via `setup --restrict`; working-tree deltas reported neutrally (a general task may legitimately edit files).
- `skills/reviewer/references/`: `code-review.md` (axes adapted from `code-review` in mattpocock/skills, MIT) and `general-review.md`.
- `--prompt-file <path>` / `--stdin`: task text from a file or stdin, for long prompts that fought shell quoting. Exactly one task source per call.
- Automatic `.agy-staff/` hygiene: on first use the companion appends `.agy-staff/` to `.git/info/exclude` (never the tracked `.gitignore`).
- `wait` heartbeats (~15s, stderr) and documentation of its unbounded `--timeout`.

## Fixed

- `triageResult` discarding complete responses on non-`SUCCESS` status (see Highlights).
- The `Likely causes: invalid model id / expired auth / exhausted quota` line was appended unconditionally; each hint now appears only when the error text matches it.
- Multi-job collection had no stated rule, making a serial `wait a; wait b` loop the path of least resistance; the rule (one job, one background `wait`) is now stated at every decision point, including the job-start output itself.

## Changed

- The `jobs` skill slimmed to the hot path; setup flow and troubleshooting moved to `skills/jobs/references/`; the hand-copied model-id list deleted (the companion's pre-flight error already carries it).
- Persona skills no longer embed copies of the wait contract — a one-line pointer to `jobs`, with the authoritative hint in the companion's runtime output.
- Docs and the design diagram reflect the five personas; tested agy version updated to v1.1.15.

## Upgrading

Both harnesses install a copy — re-run the install to pick up 0.4.0:

```bash
claude plugin marketplace update agy-staff && claude plugin install agy@agy-staff
```

```bash
codex plugin marketplace upgrade && codex plugin add agy@agy-staff   # then restart Codex
```

Muscle-memory note: the three renamed invocations (`review`→`reviewer`, `research`→`researcher`, `implement`→`implementer`) fail as unknown after upgrade; everything else, including all companion subcommands and flags, behaves as before.
