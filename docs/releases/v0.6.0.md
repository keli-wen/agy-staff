# agy-staff 0.6.0 — Streaming observation and explicit recovery

## Highlights

Implements [#13](https://github.com/keli-wen/agy-staff/issues/13): background staffer, research, review, implement and their continuations continuously drain AGY streaming JSON and publish bounded per-job observations. Synchronous ask keeps its existing execution path.

- `observe <id>` returns immediately. `wait <id> --timeout 10m` returns the existing final result on completion or an observation on soft expiry; the worker continues. Running snapshots contain five recent tool activities, merged response text, timestamps, explicit truncation and detail pointers within an 8 KiB UTF-8 JSON budget.
- Workers explicitly pass AGY `--print-timeout 60m` and enforce an independent overall hard limit, default/max 60m. Launch `--timeout` can shorten that limit. Wait/observe never renew it. Hard expiry reports `hard_timeout` with retained logs, last observation, conversation and original configuration.
- `continue --job <id> --prompt "..."` and `restart <id>` create linked jobs with fresh budgets, preserving the original terminal record. Continuation inherits the original mode/model/profile instead of an unrelated `state.last`. Recovery remains an explicit orchestrator decision after inspecting partial workspace changes.
- Cancellation stops the job's execution group and identified descendants, escalating after a bounded grace interval. Process birth stamps protect recorded descendants against PID reuse. A restricted host that prevents process inspection gets an explicit diagnostic warning.
- Lifecycle writes use a short lock; snapshot updates stay outside the shared registry. Results and terminal metadata are published before warning-free successful intermediates are removed. Exceptional jobs retain streams/snapshots; existing results, diagnostic logs and AGY conversation storage remain available.
- Crash-without-result reports include dispatch/worker-start evidence, process information, log existence/size and recovery/inspection commands. Canonical skills, generated Pi skills and bilingual references explain attention intervals and host scheduling limits consistently.

The command and storage contract is documented in [REFERENCE.md](../REFERENCE.md#state-and-background-jobs). The agreed design remains in issue #13; this release does not include local blog research material.

## Local trial feedback

Wait now remains silent until a result or soft-expiry snapshot is ready. Removed the unconditional 15-second liveness heartbeat. Skills explicitly call observe before a mid-run progress report and distinguish job observation from host session collection, avoiding repeated short empty polls. A regression test waits beyond the former heartbeat interval and verifies silent waiting plus intact snapshot/result delivery.

## Validation

The offline suite covers parsing, UTF-8 byte budgets, late step updates, soft/hard expiry, wait interruption, observer independence, concurrent lifecycle writes, error/warning compatibility, recovery configuration, result/cleanup races and termination-resistant descendants. Packaging tests check version alignment and the actual npm archive; generated Pi skills are checked separately.

Real AGY 1.1.27 smoke tests on macOS exercise streaming tool output (including a command exiting 7), structured review output, cancellation after a shell tool starts, and a shortened hard deadline after a shell tool starts. Process snapshots check observed CLI/tool descendants and ensure stopped tools do not write completion markers. Reproduce with `AGY_REAL_SMOKE=1 node tests/real-agy.integration.mjs` in an unsandboxed context with an authenticated AGY installation. It makes model calls only in disposable directories and prints the evidence location.

These tests exercise the lifecycle paths requested by [#4](https://github.com/keli-wen/agy-staff/issues/4) and [#8](https://github.com/keli-wen/agy-staff/issues/8). A shortened deadline is not a full-hour endurance test; process observations cover the tested process trees, not every possible daemonization strategy or operating system. Workspace attachment (#9) and permission allowlist granularity (#10) remain separate.
