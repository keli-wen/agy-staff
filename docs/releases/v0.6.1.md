# agy-staff 0.6.1 — Recovery follow-ups and quieter delegation

## Changes since 0.6.0

0.6.0 already introduced streaming observation, `continue --job`, `restart`, early conversation persistence and recovery using the original job configuration. This release builds on those mechanisms.

- [#8](https://github.com/keli-wen/agy-staff/issues/8): recognize AGY's `ERROR` / `timeout waiting for response` payload in addition to explicit response-timeout statuses. An empty response at a response deadline or worker hard limit with a known conversation now yields `attention` (exit 5), with a suggested continuation timeout and an explicit user-confirmation requirement. Failure reports include bounded pre-run/current workspace status. Historical foreground `ask` configurations are indexed by conversation ID so subsequent calls do not erase them. Complete responses still succeed with warnings; unrelated errors retain their classification. No automatic retry or continuation is introduced.
- [#9](https://github.com/keli-wen/agy-staff/issues/9): foreground and background calls share argument construction and pass `--add-dir <repoRoot>`, falling back to the launch directory outside Git. This attaches the intended workspace instead of relying on AGY to infer it from the prompt or inherited cwd. Both restricted and unrestricted calls receive it; unrestricted still uses `--dangerously-skip-permissions`. Continuation and restart retain their original workspace selection.
- [#10](https://github.com/keli-wen/agy-staff/issues/10): optional setup retains broad git/gh grants and adds five deny prefixes (`git push`, `git reset --hard`, `git clean`, `gh pr merge`, `gh release delete`) through AGY's native permissions. This addresses the issue with a small deny list instead of maintaining a per-subcommand allowlist. It only configures restricted use; default unrestricted tasks do not depend on setup. Dry run shows both lists, apply backs up and appends missing rules, and existing allow/deny/ask settings are preserved. Malformed settings fail without being overwritten. The deny prefixes prevent common mistakes, not all irreversible actions or alternate command forms; the companion adds no matching engine or new mode.
- Delegation guidance: default to prompt → dispatch → wait for the final result → validate as needed. Observe progress only on an explicit user request; diagnose after failure or a result requiring intervention. Keep necessary host result collection and the persona → jobs division. Remove invitations to inspect progress for routine updates from skills, CLI launch text and bilingual documentation. The wait/observe implementation and output schemas remain intact; a wait soft expiry still returns a snapshot and leaves execution running. Reduced live-session token usage has not been measured.

Package, Claude Code and Codex manifests are aligned at 0.6.1. Canonical skills and generated Pi skills are synchronized. `wait`, `observe`, `status <id>` and `result` return exit 5 for attention; `result` retains its historical exit behavior for other terminal states. Existing 0.6.0 terminal records are not migrated.

## Validation

The complete offline suite passed 168 tests on the final PR contents, including allow/deny merging, deny-only upgrades, malformed-settings protection, recovery, workspace attachment and delegation guidance. Earlier targeted guidance validation also passed 61 dispatch, wait, observation and packaging tests. Generated Pi skills, `git diff --check` and local npm archive validation passed. The README diagram was regenerated and visually inspected.

A real AGY 1.1.27 restricted staffer run read a marker file from a disposable non-Git workspace. This verifies the tested workspace-read path. Offline timeout fixtures cover known response shapes; the subsequent live lifecycle test below exposed an additional native behavior.

## Live validation on AGY 1.1.28

An independent Codex agent exercised the real CLI in disposable workspaces using `gemini-3.8-flash-low`. Unrestricted subdirectory execution and relative reads passed; continuation invoked from the repository root restored the original subdirectory and conversation; non-Git reads passed. A restricted native-file read also succeeded using the existing configuration unchanged; `view_file` required an absolute path, which AGY resolved from the supplied original working directory. This does not verify deny enforcement. The existing opt-in lifecycle harness passed streaming output, structured review and cancellation, with no observed surviving execution processes.

The hard-timeout case failed. At the 35-second limit, AGY terminated an unfinished background command but returned a `SUCCESS` result containing only a launch/wait message. The companion consequently reported `done` / exit 0 instead of timeout attention / exit 5. The recorded native diagnostics were:

```text
root agent idle; waiting for 1 background task(s) (bounded by --print-timeout)
terminating 1 background task(s) on exit
```

This timeout was intentional: the test requested a 90-second command with a 35-second limit. Background jobs normally default to 60 minutes. The native CLI exited just before the companion's independent hard deadline, so the companion's hard-timeout handler did not fire. The failure is incorrect completion classification after unfinished work, not evidence that normal tasks spontaneously time out after 35 seconds. The original #8 report instead describes a 10-minute implement run that retained partial changes and returned `ERROR` / `timeout waiting for response`; it does not establish why that task needed more time.

Reproduce the lifecycle case with `AGY_REAL_SMOKE=1 AGY_CLI_DISABLE_AUTO_UPDATE=1 node tests/real-agy.integration.mjs` in an authenticated, unsandboxed context. This remains an open validation failure; the offline suite does not cover this native SUCCESS-with-unfinished-background-work behavior.

Isolated setup generation produced the expected nine allow and five deny rules. After explicit authorization for temporary authentication copies, both isolated control attempts still required interactive login and expired after 60 seconds, before any model or tool ran. No allowed control or denied command executed, so native deny enforcement remains unverified. Both temporary HOME directories, including authentication material, were removed; real settings and credentials were unchanged. Further live policy testing needs an authenticated disposable HOME or a verified configuration-isolation mechanism.
